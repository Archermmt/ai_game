## 1. 产品定义

玩家以俯视视角，在平静海面上涂出沙滩、草地与石台地，铺上小路和木桥，放下几间小屋。小屋会根据周围的花园与海岸改变外观；码头接通后，旅人带着行李入住。玩家从居民的生活片段中发现小愿望，再用一张长椅、一座茶屋或一片花圃，把岛变成愿意停留的地方。

**核心体验承诺：一笔有变化，几分钟有生活，一次游玩留下一张自己的岛屿明信片。**

| 项目 | 本案决定 |
| --- | --- |
| 暂定名称 | 风屿手记 / Breezely Isles，正式名称在发行准备阶段另行确认 |
| 类型 | 治愈系海岛建造、轻居民模拟、创作沙盒 |
| 目标用户 | 喜欢微缩场景、布置与观察日常的玩家；每次可玩 15–45 分钟，也允许长时间搭建 |
| 首发方向 | PC 单人，键鼠优先；首版界面简体中文，文本留本地化键 |
| 视角 | 3D 正交相机，默认俯角 45°，水平每次旋转 90°；模型需能四面观看 |
| 交互角色 | 玩家是画岛的人，无需操纵角色搬运与采集 |
| 情绪关键词 | 松弛、轻盈、温暖、被回应、生活逐渐发生 |
| 商业方向 | 优先验证买断单机；价格、销量与收入目标不在本轮假设中 |
| 工程建议 | 采用 Godot 4.x 做 3D 原型；具体版本与渲染路径在技术验证时锁定，当前目录尚无引擎工程 |

### 1.1 与参考作品的关系

参考依据为 [Brushland 官方 Steam 页面](https://store.steampowered.com/app/5163450/Brushland/)，查阅日期 2026-10-28。该页当时标为尚未发售。公开介绍展示了涂画地形、建筑响应邻接、船只迎来居民、无失败和可撤销等方向。本文没有对该作进行实际试玩；以下系统数值与制作方案均为本项目原创提案。

| 参考体验方向 | 本项目的设计回应 |
| --- | --- |
| 用少量工具塑造地形 | 一支地貌笔，四种地表，有限高度，让海岸线成为主要创作对象 |
| 环境影响建筑 | 先做居所的三种确定性外观；悬停能看原因，玩家能锁定喜欢的造型 |
| 观察居民生活 | 用散步、喝茶、看海和摆弄花草形成可见反馈，愿望只是下一笔的灵感 |
| 轻松的创作节奏 | 免费放置、随时撤销、无倒计时和负向经济，允许只搭风景 |
| 微缩景观的整体观感 | 延续圆润体块、柔光与色块层次；以海湾、温室、茶屋和灯塔形成自身主题 |

本案的辨识度来自**海岸构图、生活片段手记、可解释且可锁定的建筑响应**。不沿用参考作品的城堡、教堂等建筑轮廓、命名、界面图标或素材。

### 1.2 首轮需要验证的三件事

1. 没有经济压力时，画海岸和观察外观变化本身能否支撑连续 15 分钟的兴趣。
2. 玩家能否理解“为什么变成这个样子”，并感到自己仍然掌握最终外观。
3. 六种建筑外观、少量摆件与居民动作，能否组合出明显不同的三处岛上风景。

## 3. 玩法循环

```mermaid
flowchart LR
    A[画出一段海岸] --> B[铺路与摆屋]
    B --> C[环境响应外观]
    C --> D[码头接通 居民入住]
    D --> E[观察生活与小愿望]
    E --> F[补一处喜欢的风景]
    F --> G[收录手记 拍一张明信片]
    G --> A
```

- **10 秒反馈**：画出岸线，边缘变圆，浅水泛起涟漪；放下房屋，门窗和屋顶轻轻弹入。
- **2–5 分钟反馈**：一小片海岸形成完整构图，第一位居民踏上码头，花园令小屋换上花箱与遮阳棚。
- **15–30 分钟反馈**：港湾、花园和灯塔步道有了不同活动，手记留下一次喝茶或看海的片段。
- **长期动力**：尝试新的岛形、路径和配色，保存自己的场景。MVP 验证创作深度，不承诺长篇剧情时长。

### 3.1 首次 30 分钟体验脚本

时间为设计节奏参考，无计时考核；每一步可跳过。

| 建议时间 | 玩家行为 | 系统反馈 / 观察重点 |
| --- | --- | --- |
| 0–2 分钟 | 选择预设海湾，学会拖动相机与画草地 | 海水、岸线和草地立即更新；一个提示只教一个动作 |
| 2–5 分钟 | 放一间居所，画到门口的小路，放码头 | 用虚线标出门与道路、道路与码头的接通状态 |
| 5–8 分钟 | 看第一位旅人抵达并入住 | 不弹强制长对话；出现可展开的名字与一句日常心声 |
| 8–12 分钟 | 在屋旁画三格花圃 | 显示“周围的花让这里成了花园小屋”；可对比并锁定 |
| 12–18 分钟 | 按“想找个地方坐着看海”摆下长椅 | 居民沿路走到座位；手记记录一个片段 |
| 18–24 分钟 | 跨浅湾搭短桥，放温室与茶屋 | 看见两位居民在设施之间来往，练习撤销一次 |
| 24–30 分钟 | 在高处放灯塔，切换日落，隐藏 UI 拍照 | 保存明信片；展示“还想再画一笔，或下次再来”式轻提示 |

## 4. 世界与地形编辑规则

### 4.1 统一标尺

| 参数 | 首版约定 |
| --- | --- |
| 世界格 | 1 格 = 1 m × 1 m；只用于逻辑、拼装与占地，正常游玩隐藏网格 |
| 高度 | h=0 为海面 / 水格；h=1–4 为陆地，每级 0.5 m |
| 地表约束 | 海水仅 h=0；沙地可 h=1–4；草地 / 岩台可 h=1–4，临水边自动添加岸缘 |
| 地形笔 | 地表选择 + 升 / 降；半径 1 / 2 / 3 格；显示本次覆盖轮廓 |
| 路宽 | 1 格，显示宽度约 0.65 m，留出路边摆件空间 |
| 建筑占地 | 全部 2×2 格；居所檐高约 1.8 m，总高约 2.8 m；灯塔总高约 5 m |
| 居民身高 | 约 1.0 m，比例有意偏童话；头部约全高的 1/3 |
| 编辑区 | 64×64；外圈海面为背景，不可越界放置 |

花圃是草地上的独立覆盖标记，通过“自然”工具绘制；不能画在沙地、岩台、水格或建筑足印内。改变底层地表时预览会标出将被清除的花圃，撤销同时恢复标记与表现。

地形以格存储，渲染采用圆角拼装或分块网格。岸缘只处理视觉过渡，不做真实流体。美术概念图中的悬崖高度和细节密度是氛围参考，实际首版按上述高度上限制作。

### 4.2 一笔的行为

1. 按住拖动时只生成预览；同格在一笔内只应用一次，避免停留导致无限叠高。
2. 抬手后作为一个事务提交：地表 / 高度 → 岸缘与坡道 → 道路拓扑 → 建筑邻接 → 居民目标校验。
3. 同一格的数据、种子、规则版本不变时，结果必须一致。随机装饰以稳定 ID 派生，不随相机或帧率重抽。
4. 相邻高度差为 1 且有道路连接时，沿路自动生成坡道 / 阶步视觉；高差大于 1 为不可直接步行的崖面。需要玩家拉出更长缓坡。
5. 提交前显示受影响的范围。安全检查不通过的格以斜纹与原因提示，整笔跳过这些格，其余有效格仍可应用。

### 4.3 安全编辑与撤销

- 地形笔不改变建筑四格基础、桥的陆地桥头与码头陆地锚点的支撑高度，也不把这些格涂成海；显示“先移动上面的物件”。
- 大型树木与摆件占用格同样保护支撑高度，改成水或升降时跳过；玩家可用移动或独立移除工具处理，不让普通造地笔暗中删物件。
- 桥跨水格、码头伸出格与泊位记录水域占用，地形笔不能把它们抬成陆地。远处航路不受保护，改建后可使码头失效；有效水域占用随设施移动 / 移除一起更新。
- 道路可被地形覆盖而移除，预览中显式标出。站在该路上的居民暂缓当前活动；居民不因编辑受伤。
- 居民脚下地面升降后重新贴地；改为水时，从编辑前所在连通区域中寻找提交后仍有效的最近站位，无站位则进入手记中的“暂歇”状态。重新出现可达居所后，从有效位置恢复。
- 撤销重做至少记录 50 个编辑事务，每一笔 / 一次放置 / 一次移动为一步。恢复地形、物件、外观锁定及受影响的居民归属；居民走路动画不要求倒放。
- 在编辑事务期间暂停受影响区域的行为调度；一次提交完成后再恢复，避免半成品布局触发来客或愿望。
- 撤销历史仅保证当前会话；重载后保留最终世界与居民记录，不承诺跨会话撤销。
- 撤销先恢复编辑数据，再校验全部床位、在途预约和站位；期间新产生的居民档案不删除。无法回到有效床位的居民暂歇，已收录手记保留，不重复触发。新编辑会清空重做分支。

## 5. 路网、建筑与邻接响应

### 5.1 放置与连通

建筑预览显示 2×2 占地、入口方向与邻接结果。四格需为同高陆地，入口朝向可每次旋转 90°；门前一格需与基础同高、可放路或已有小路，作为入口预留格不能被实体摆件占用。绿 / 斜纹并配文字表示可放 / 受阻，不只依赖颜色。

居所能够在未通路时作为景观存在，状态显示“还没有通往码头的小路”，不冒出催促警告。居民入住要求：有效码头 → 可步行道路 / 桥 / 坡道 → 居所入口，且存在空床位。

道路四方向连接；仅相邻同高地面、合法坡道和桥可产生边。普通草地不充当入住路网，居民可在设施的预设活动点做小范围漫步。摆件不能堵住门前格、桥面或唯一通行宽度；放置预览说明受阻原因。

| 设施 | 放置约束 | 功能与反馈 |
| --- | --- | --- |
| 木桥 | 直线，横跨 2–6 个连续水格，两端陆地等高且 h=1–2；桥头需接路 | 自动填充中段和栏杆；非法跨度只预览不提交 |
| 码头 | 一个 h=1–2 的陆地锚点 + 沿面朝方向 2–4 个连续水格；侧边留 1×3 水格泊位 | 锚点接路后才是有效入口；MVP 一次最多一条来客船，船长约 3 m、宽 ≤0.9 m |
| 航路 | 从泊位水格按四邻接水格能到达地图边缘；桥下与其他物件占用的水格不作为船路，本站泊位为端点例外 | 内陆封闭湖中的码头只作风景，提示“这里的水还没有通向外海”；小舟仅做单船来客与靠泊表演，不做交通避碰或航运经济 |
| 长椅 | 在路旁占 1×1 格，座位前有可达活动点 | 提供坐下与看海活动，不产生收益 |
| 茶屋 | 2×2，同高地面，入口接路，拥有 2 个活动点 | 居民走近、坐下、喝茶，活动点满则选其他事情 |
| 温室 | 2×2，入口接路，1 个活动点 | 观察 / 浇花动作，无采集、收成或库存 |
| 灯塔 | 2×2，入口接路；不要求临海以保障创作自由 | 手动日落时亮灯；高处临海更容易形成“望海”手记片段 |

删除或阻断码头只暂停新来客；现有居民留在岛上。桥被移动后重新校验活动，失去目标路线的居民回到同一区域的安全点，或暂歇等待恢复。

### 5.2 六种建筑外观，四种功能

| 外观 ID | 外观 | 功能 | 生成方式 / 标志 |
| --- | --- | --- | --- |
| BLD-01 | 基础居所 | 1 个床位 | 居所默认形态；奶油墙、圆角坡屋顶 |
| BLD-02 | 海岸居所 | 1 个床位 | 环境响应；蓝灰屋顶、小门廊、绳结或遮阳棚 |
| BLD-03 | 花园居所 | 1 个床位 | 环境响应；花箱、绿百叶、局部攀藤 |
| BLD-04 | 温室 | 公共活动点 | 玩家直接放置；玻璃穹顶 / 拱顶，以项目资源套件最终版本为准 |
| BLD-05 | 茶屋 | 公共活动点 | 玩家直接放置；开放式小亭、茶桌与茶具 |
| BLD-06 | 灯塔 | 景观与公共活动点 | 玩家直接放置；短圆塔、珊瑚帽、暖色灯窗 |

这里的 BLD 编号为玩法外观 ID；美术资源使用资产清单中的独立 ID，通过建筑定义表映射。三种居所共用基础壳体、占地、入口和床位，切换不会改变居民身份。居所不会自动变成温室、茶屋或灯塔。

### 5.3 可预览、可锁定的响应规则

- **检测范围**：2×2 居所外一圈的 12 格（4×4 去除中心 2×2，含四角）用于花圃计数；距离按足印格到目标格的最小曼哈顿距离计算。角格计外观但不产生对角通行。
- **花园居所**：12 格中至少 3 格带花圃标记；装饰盆栽不重复算入地表花圃。
- **海岸居所**：足印到水格的距离 ≤2，且存在一条长度 ≤2 的四邻接最短路径，沿途格不高于房屋基础。花园条件不成立时启用。
- **基础居所**：以上条件均不成立。
- **优先级**：外观锁定 > 花园 > 海岸 > 基础。邻接更新只在一笔提交后做一次，不在拖动每帧来回切换。
- **预览说明**：例如“新增 1 格花圃后：海岸居所 → 花园居所”；悬停检测圈能看到计数。
- **外观锁定**：锁的是建筑外观类别，之后可改屋顶颜色；环境变化时显示一枚小锁，不强制回退。解锁立即按当前环境重算。
- **配色独立**：屋顶可选珊瑚 / 海盐蓝 / 鼠尾草三色，属于材质参数，不增加独立建筑模型数量。

## 6. 居民、愿望与手记

### 6.1 居民模拟

| 项目 | 首版规则 |
| --- | --- |
| 外观 | 旅人、园艺爱好者、茶友、守灯人四个形象；只是外观与偏好，不构成职业经济 |
| 入住 | 每间居所 1 位，上限 12 位；空位可达且有有效码头时，约 20–40 秒展示一次来客机会 |
| 节奏 | 首次有效空位可在 10 秒内触发第一位旅人；之后按可配置间隔调度，拒绝或忽略不损失 |
| 活动 | 休息 → 选可达活动点 → 走路 → 看海 / 喝茶 / 赏花 / 招手 → 再选；活动点有预约防重叠 |
| 偏好 | 每人 1 项偏好，用于调整活动权重，不产生必须满足的数值条 |
| 路线中断 | 取消活动点预约，寻找同一连通区域内的可达目标；无站位进入暂歇，不反复卡在墙边 |
| 删除居所 | 用独立移除工具执行，保留居民档案；若有其他可达空屋则搬入，否则暂歇，不死亡、不扣分 |
| 动物 | 猫与海鸥总共最多 6 只，按预设出生点 / 栖息点活动；无喂养与繁殖系统 |

有有效空房时先安置暂歇居民，再接待新来客。已登船或在码头等待的来客要预留床位并计入 12 人上限；抵达前再次检查码头、居所和路线，失效则等待重新分配或暂歇，不能按旧路径直接入住。

模拟可暂停，编辑仍可进行。当前没有合适条件时不发送来客，也不强制补房。小岛被完全清空后，手记仍保留已发生的记录。

### 6.2 六条首版愿望

每次最多显示 3 条；不计时、不扣好感、可收起，完成后不会因玩家改建而撤回奖励。只从当前岛上可以达成的条件中选取，连续两条不重复。

| 愿望 | 可执行条件 | 完成反馈 |
| --- | --- | --- |
| “想找个地方坐着看海。” | 路网可达长椅；座位距海 ≤3 格，朝向 3 格内有水面 | 一次坐下看海；收录“海风座位” |
| “门口有点花就好了。” | 本人居所外圈有 ≥3 格花圃 | 花园居所预览、一次赏花；收录“第一簇花” |
| “想请邻居喝杯茶。” | 茶屋可达且同时有两位居民能到达它的活动点 | 一次双人喝茶；收录“茶还温着” |
| “那边的小路，也想去走走。” | 两个有居民的陆地区域被合法木桥接通 | 一次过桥；收录“桥的另一头” |
| “喜欢有玻璃屋的花园。” | 温室可达，周边一圈有 ≥3 格花圃 | 一次温室赏花；收录“玻璃里的绿意” |
| “傍晚一起看灯亮吧。” | 灯塔可达，手动切换日落，有居民抵达塔外活动点 | 一次望灯；收录“今晚有灯” |

条件满足后允许 10–20 秒的自然调度；持续不可达时显示原因，不假报完成。愿望完成奖励为一句感谢与手记插页，不使用货币，也不限制玩家建造权限。

愿望实例绑定提出者和目标对象 ID，只有对应活动真正完成才收录。茶歇由一次活动协调两位可达居民并同时预约两处座位；“桥的另一头”绑定具体桥，需提出者实际走过桥。判定两个陆地区域时不包含桥的连接边，且只在有合法 2–6 水格跨距时选该模板。条件中断则取消预约、稍后重试。

### 6.3 手记与拍照

手记是一组可回看的生活片段：缩略图、标题、居民名字、一句短句。MVP 共 6 个对应上述愿望的条目；重复事件可刷新最近截图，不无限增长存档。可以只拍场景，不完成愿望。

拍照模式隐藏 UI、冻结 / 恢复居民、切换午后 / 日落、调整相机缩放与方向；保存无水印 PNG。默认输出 1920×1080，允许使用当前窗口分辨率。图片写入用户数据目录，显示“打开所在文件夹”，不自动上传。

## 9. 美术方向与概念设定

### 9.1 视觉规范

目标是**可以转动观看的手作海岛模型**。建筑先读出墙身、屋顶、门廊三层体块；植物先读出冠形，最后才是叶片。减少高频纹理，让地形变化、入口与居民始终易读。

| 维度 | 制作约束 |
| --- | --- |
| 形状 | 圆角墙体、厚屋檐、短胖塔身；避免过细尖塔与尖锐写实岩片 |
| 材质 | 哑光灰泥、轻木纹、釉陶、柔和石灰岩；金属只在小范围有高光 |
| 笔触 | 通过低频色差、顶点色与少量贴图表现手涂感，不靠满屏噪点 |
| 光照 | 暖主光、偏青的柔影、环境遮蔽；阴影不能黑到吞掉门窗 |
| 水面 | 浅青近岸与更深青的外海渐变；低幅波纹、浅岸泡沫，避免镜面闪烁 |
| 植物 | 一棵圆冠主树 + 瘦长树作为对比，灌木成团；花只作少量视觉标点 |
| 建筑家族 | 奶油墙、珊瑚 / 海盐蓝 / 鼠尾草屋顶、木质小部件；四种功能一眼可辨 |
| 居民 | 约三头身，面部简化，服装靠大色块区分；发丝、针织和手指细节在生产时简化 |
| 动画 | 环境慢、点击反馈短；建筑生成 0.25–0.4 秒，禁止持续呼吸缩放整座房屋 |

| 色名 | 建议色值 | 用途 |
| --- | --- | --- |
| 奶油白 | `#F3E8CE` | 墙体、UI 底色 |
| 珊瑚陶 | `#D88D75` | 屋顶、少量服装重点 |
| 海盐蓝 | `#789AA8` | 屋顶、门窗、阴影过渡 |
| 鼠尾草 | `#95AC87` | 灌木、屋顶变体 |
| 深苔绿 | `#536F60` | 树冠内部与结构区分 |
| 浅湾青 | `#9BCAC5` | 浅海主色 |
| 暖沙色 | `#DEC9A5` | 沙滩、小路 |
| 蜂蜜黄 | `#E8C575` | 窗灯、旅人斗篷、交互强调 |
| 墨灰绿 | `#384D48` | UI 正文，确保浅底可读 |

色值是材质与界面的起点；概念图包含更丰富的明暗，不应逐像素取色替代引擎内调色。

### 9.2 建筑与道具设计板

![六种建筑外观与自然、基础设施、摆件设计板](concepts/03_prop_building_board.png)

第一行从左到右为六种建筑外观；第二行是树木、灌木、花、岩石、桥、码头与岸缘；第三行是长椅、茶桌、邮箱、盆栽、木箱、灯笼、系缆桩和路牌。建筑三种居所共用主体；盆栽与花箱同时用于立面附着件和自由摆放。

![四种居民形象与猫、海鸥动作设定](concepts/04_residents_board.png)

| 形象 | 识别物与主色 | 性格语气 | 优先动作 |
| --- | --- | --- | --- |

| 园艺爱好者 | 绿背带裤、宽檐帽、陶盆 | 喜欢分享刚开的花 | 看花、浇水、整理帽檐 |

### 9.4 概念图交付与边界

本次交付四张原创 AI 概念图，使用内置 `image_gen` 生成，已全部保存到本项目；它们用于气氛、构图和造型沟通，尚不是游戏可加载的 3D 资产、动画或 UI。最终提示词见 [concepts/prompts.md](concepts/prompts.md)。

## 10. 美术资源交付规范

| 类型 | 首版交付格式与技术要求 |
| --- | --- |
| 模型源文件 | `.blend` + 导出 `.glb`；单位米，变换应用，正面朝向与导入约定统一并在样例资产中验证 |
| 静态网格 | 原点在地面中心；地形模块以格角 / 明确插槽为锚点；入口、桥头与活动点有命名定位节点 |
| 预算 | 小摆件 ≤500 三角面；树木 ≤1,500；单栋居所 ≤3,000；温室 / 茶屋 ≤4,000；灯塔 ≤5,000；居民 ≤2,500；猫 / 海鸥 ≤1,200 |
| 材质与贴图 | 环境共享色板 / 图集 1024–2048；小物优先共用材质；单个静态道具原则上 1 个材质槽，建筑最多 2 个，居民最多 2 个 |
| 碰撞与通行 | 简化盒体 / 凸体，避免逐三角碰撞；非交互花草不设物理碰撞，格占用与人物路径分别配置 |
| 角色动画 | 一个共享人形骨架；原地循环动画，由路径系统驱动位移；坐姿与设施坐点共同验收 |
| 动物动画 | 猫与海鸥各一套骨架，不承诺人形复用；起落与航线是表演，不建立完整鸟类模拟 |
| UI | 可编辑矢量源 + 必要的 1×/2× PNG 导出；工具图标 32 / 64 px，物件缩略图 128 / 256 px；透明边无白晕 |
| VFX | 低粒子量、少透明叠层；风摆优先着色器，岸缘泡沫优先贴岸条带；必须有减少动画开关 |
| 组合场景 | `.tscn` 或等效引擎场景引用共享模型，不重复导出同一几何；同时交灰盒占地与活动点示意 |

采用 Godot 时，交换文件优先使用官方支持的 glTF 2.0 / `.glb`，`.blend` 保留为可编辑源件；导入后检查尺度、Y 轴朝上、材质与动画。[Godot 官方格式说明](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html) 与 [3D 单位、坐标及相机说明](https://docs.godotengine.org/en/stable/tutorials/3d/introduction_to_3d.html) 为技术验证依据，查阅于 2026-10-28。

建议目录按功能分组，例如 `game/world/`、`game/building/`、`game/resident/`、`game/ui/`；每个功能内再区分模型、材质、场景与脚本。文件使用 `snake_case`，场景节点使用 `PascalCase`。这只是未来工程约定，本次不创建空的游戏目录。

资源命名示例：`cottage_shell_a.blend`、`cottage_shell_a.glb`、`cottage_coast.tscn`、`mat_roof_coral.tres`。资源清单 ID 是稳定追踪键；运行时另建定义表关联，不把展示中文写入资源引用路径。

### 10.1 通用美术验收

1. 默认相机下能区分入口与正面，旋转四次无破面、悬空或背面缺失。
2. 所有建筑放在 2×2 灰盒中验证，附件不越出可阻挡区；伸出的屋檐只占视觉空间。
3. 岸缘至少校验直边、凸角、凹角、窄水道和高差转角；桥头与坡道接缝无可见漏水。
4. 角色脚底贴地，坐姿不穿椅；茶杯 / 灯笼 / 行李箱与手部挂点一致。
5. 午后与日落都能看清模型轮廓；缩至正常游玩尺寸后无纹理闪烁。
6. 模型、材质、图标与资产 ID 一致；记录原件、变体与组合关系，不能把调色复制件重复计为新模型。

## 13. 数据、保存与性能基线

本节是原型实现约束，不代表已实现功能。尽量用可配置规则表支持美术迭代。

| 数据 | 最小字段 |
| --- | --- |
| Tile | x / z、高度、地表、道路、花圃标记、占用 ID；稳定视觉种子 |
| Building | 实例 ID、功能类型、外观 ID、位置、朝向、配色、外观锁定、入口与活动点 |
| Prop | 实例 ID、资产 ID、位置、朝向、占地、活动点类型 |
| Resident | 稳定 ID、外观、名字、偏好、居所 ID、当前有效位置 / 暂歇状态 |
| Wish | 条目 ID、关联居民、条件参数、是否收起、完成标记 |
| Journal | 六条记录的解锁状态、短句键、最近截图引用 |
| Save | schema_version、rules_version、seed、世界与实体、手记、相机与设置 |

存档使用版本号与原子写入，只读取完整提交态；自动保存每 60 秒且无进行中编辑时触发，退出时保存。保留最近 3 次自动备份与 3 个命名手动槽；写入失败时保留旧文件并提示可重试。重载恢复世界、锁定外观、居民身份、愿望和手记，并重新校验在途床位预约；瞬时动画可以重新进入合理状态。保存路径使用引擎用户数据目录，不写进安装目录。

| 性能验证项 | 目标场景与门槛 |
| --- | --- |
| 代表性场景 | 64×64 格；1,200 格陆地、约 2,896 格水；40 个建筑实例（含 12 居所）；400 个装饰实例；12 居民、6 动物 |
| 参考设备 | Apple M1 / 8 GB、1920×1080 中等画质作为首轮测量基准；Windows 对照设备另行选定 |
| 帧率 | 代表性场景目标 ≥60 fps；最低可接受 30 fps 档，需通过画质选项实现而非限制基础操作 |
| 编辑 | 笔刷预览应在下一帧可见；普通一笔提交到稳定显示 p95 <100 ms，超预算时分块处理 |
| 渲染预算 | 可见网格三角面目标 ≤350k，绘制调用目标 ≤200；透明区域与灯光数量优先控制 |
| 内存与读取 | 峰值进程内存目标 <1.5 GB；本地地图加载目标 <5 秒；均需实机验证 |

先做占地、导航和撤销原型，再确定地形拼接与水面方案；居民使用轻量活动状态机，编辑后的路网只更新脏区域。重复植被与摆件优先实例化，静态图集与材质共享优先于增加模型细节。

## 14. 开发顺序与完成门槛

按 1 名玩法程序 + 1 名 3D 技术美术 / 美术可投入的情况估算，以下 8–10 周只是排期草案；不把 AI 概念图等同于完成建模工时。进入下一阶段以验收结果为准。

| 阶段 | 建议时长 | 必须可检查的成果 |
| --- | --- | --- |
| M0 交互灰盒 | 1 周 | 正交相机、画地、占地、一次操作一次撤销；无美术也能完成一小块岛 |
| M1 建岛闭环 | 2 周 | 路、桥、码头、三种居所外观规则、锁定、第一位居民可达入住；基础存档 |
| M2 垂直切片 | 2–3 周 | 一套正式材质，六种建筑外观、完整 S01 与 S02，愿望 → 活动 → 手记链路 |
| M3 内容与收尾 | 2 周 | S03、居民与动物、两套光照、拍照、资源清单 MVP 项齐套 |
| M4 体验验证 | 1–2 周 | 性能基线、异常编辑、保存恢复、可用性测试；修复阻断再评估后续内容 |

若排期超出，先减少 P1 的装饰变体、个性动作与音频变化；保留画地、路网、居所响应、居民入住、撤销与保存。P0/P1 是制作顺序，清单中标 MVP 的 P1 仍属于完整首版目标；任何裁剪需同步改本表与清单。

### 14.1 MVP 验收用例

| ID | 测试动作 | 通过条件 |
| --- | --- | --- |
| AC-01 | 从空海面拖画岸线，改变地表并连续升降 | 无裂缝与越界；一笔同格不重复升高；撤销恢复完整一笔 |
| AC-02 | 在建筑基础上尝试画海、升高与降低 | 支撑格跳过且解释原因，房屋与居民记录完整 |
| AC-03 | 居所外圈从 2 格花圃加到 3 格，再撤销 | 预览与实际一致；海岸 / 基础 → 花园 → 恢复；床位归属不变 |
| AC-04 | 同时满足花园与海岸，再锁定外观并修改邻接 | 花园优先；锁定后不自动变化；解锁按当前布局重算 |
| AC-05 | 放置空屋、连路、通海码头；再切断航路 | 首次有效条件 10 秒内触发来客；断路 / 内湖时不来客；显示准确原因 |
| AC-06 | 搭合法短桥，再试超长、异高桥与堵门摆件 | 合法桥可走；非法方案不能提交，并有文字与形状反馈 |

| AC-08 | 完成一条愿望，收起另一条，暂停并重载 | 完成不撤回，收起不惩罚；居民身份、手记和外观锁定保留 |
| AC-09 | 完成 50 次混合编辑后连续撤销重做 | 所有保留步骤可回放，世界与占地无重复物件，变体结果稳定 |
| AC-10 | 在 720p 与 1080p 使用全部工具，切至拍照 | 浮层不挡当前放置；点击 UI 不画到地面；导出图无 UI 与水印 |
| AC-11 | 让存档写入失败后恢复权限，再模拟异常退出 | 旧存档仍可读，错误可重试，自动备份能恢复最近完整世界 |
| AC-12 | 载入代表性性能场景并连续编辑、旋转 5 分钟 | 记录帧率、内存和提交耗时；满足第 13 节目标或明确降级方案 |

### 14.2 小规模体验验证

邀请 5–8 位偏好休闲建造的玩家，使用同一 30 分钟试玩脚本，录屏与记录需先获得参与者同意。通过观察验证，不在 MVP 增加在线遥测。

- ≥80% 能在 5 分钟内画地、摆屋并说明下一步如何接路。
- ≥80% 能在第一次建筑变化后说出花圃或海岸的触发原因。
- ≥80% 能独立使用一次撤销，并相信后续编辑可以恢复。
- 至少 4/5 的受试者愿意在无奖励提示时继续布置一个角落。
- 记录不理解、误删、卡路与 UI 遮挡的次数；任何导致作品丢失的问题先于内容扩充修复。

以上是小样本产品门槛，不是统计意义上的市场结论。

## 15. 风险与决策记录

| 风险 | 首版处理 |
| --- | --- |
| 画地很好看但缺乏后续动机 | 先用六个生活片段验证观察兴趣；不直接堆经济系统 |
| 自动响应剥夺设计权 | 固定优先级、提交后更新、前后预览、外观锁定，保持功能和居住归属 |
| 改地形破坏导航 | 占地安全检查与事务更新先做；居民目标和站位每次提交后复核 |
| 概念图细节导致生产成本过高 | 先做一栋居所与一段岸边样板，以默认视角读形为验收标准 |
| 水面与玻璃成本偏高 | 水面简化为浅深色与贴岸泡沫，温室减少透明层；先测低配再加细节 |
| 内容数量被变体虚增 | 独立源件、组合场景和参数变体分开计量，清单记录依赖 |
| 开放式创作难度超预算 | 限定地图、高度与直线桥；MVP 不做地下、室内和多层建筑 |

当前采用键鼠 PC、3D 正交、一套海湾美术和六种建筑外观作为初始设计决定，方便直接进入原型。手柄、发行平台细节、最终语言范围、引擎确切版本与商业价格留到对应阶段验证，不阻碍本轮设计与美术拆单。
