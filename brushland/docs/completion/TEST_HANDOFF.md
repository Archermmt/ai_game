# 风屿手记 0.3.0 可转交测试包

2026-10-30。用户暂不能安排 M1/8GB、Windows 实机和5–8人试玩，因此本次交付构建与可执行步骤。这里是测试说明，空白记录表不代表已执行；本机结果与最终人工视觉接受见项目源码 docs/completion/FINAL_REPORT.md。

## 包与正常体验

- `BreezelyIsles-0.3.0-macos-test.zip`：解压后运行 `.app`，Apple Silicon / Intel 通用模板；仅在本机 Apple M4 Pro 验证。
- `BreezelyIsles-0.3.0-windows-test.zip`：完整解压至可写文件夹，运行 `BreezelyIsles.exe`，Windows x86_64。已生成包，未在 Windows 运行。
- 包的字节数与 SHA256 见项目 `docs/reports/completion_r4/packages.json`。测试前核对包版本与哈希；保留 `licenses` 文件夹。
- macOS 为 ad-hoc 签名、未公证；Windows 未作发行者签名。若系统阻止运行，记录提示原文并联系项目负责人，不要求关闭系统保护。需要公开分发时再提供发行者签名/公证。

欢迎页的“新建海湾（无建筑）”用于首次体验；“空白海面”可完全从零画岛。三个“参观”入口是内部构图，带完整建筑，不用于计量初次建造是否成功。所有工具免费，无限资源。

鼠标左键画地/放置，抬手提交；右键/Esc取消；WASD平移、滚轮缩放、Q/E转相机、R转物件；[ ]调笔刷、−/+调桥长；Cmd/Ctrl+Z撤销、加Shift重做；空格暂停、Tab手记、P摄影、F12保存。设置里可以重绑、改音量和UI缩放。摄影退出后恢复此前的暂停状态。不要用“重做”重播居民时间。

## 标准硬件性能测试

先接电源、关闭其他高负载程序，记录系统、内存、CPU/GPU、电源模式与显示缩放。目标为M1/8GB及一台记录具体配置的Windows设备，1920×1080，中等画质。不得将其他硬件结果填进这两栏。

1. 完整解压包。macOS将 `.app` 与 `Run-Benchmark.command` 放同一目录，终端执行 `./Run-Benchmark.command medium`。Windows在该目录的PowerShell执行 `./Run-Benchmark.ps1 -Quality medium`。若组织策略禁止脚本，直接使用下方手动命令并在任务管理器/活动监视器另记内存，不修改策略。
2. 场景自动固定为64×64格、1200陆地、40建筑（12居所）、400装饰、12居民、6动物；全景旋转，前半白天后半夜景，每2秒提交一笔升/降地形。运行满300秒后自动退出。默认基准为完整窗口；可加--compact使用角落640×360预览（仍固定1920×1080渲染并校验截图尺寸），不会抢键盘焦点。测试期间保持窗口可见，不要最小化、休眠或改渲染分辨率；关闭预览会退出并记为中断。鼠标无需操作。
3. 收集 `test-results` 下日志和2秒内存CSV，以及日志 `BENCHMARK_REPORT` 所指文件夹（含report.json及每分钟截图）。若Windows控制台重定向未显示路径，请在下文用户目录的benchmarks下查找最新run文件夹，并附logs/godot.log。报告中的 `target_device_tested:false` 是防止程序自动替人签收，测试者应另填设备结论。
4. 在同一机器再测 `low`。流畅档关闭太阳阴影并减少草卡，不减少玩法对象。两档分别交回完整结果，不覆盖首轮文件夹。
5. 手工正常启动三次，记录从执行到可操作的时间（含系统提示，说明是否首次）；进入/读取自己的大岛，另测读档到可操作。`BOOT_READY_MS`只计启动场景内部加载，不包含全部系统启动时间。

手动命令（完整5分钟）：

```sh
# macOS：CFBundleExecutable可在.app/Contents/Info.plist中查看；通常为Breezely Isles · 风屿手记
"./Breezely Isles · 风屿手记.app/Contents/MacOS/Breezely Isles · 风屿手记" -- --benchmark --duration=300 --quality=medium
```

```powershell
.\BreezelyIsles.exe -- --benchmark --duration=300 --quality=medium
```

只需确认能启动时可用`--duration=10`；10秒结果不能填作5分钟验收。完整门槛：帧时p95目标≤16.67ms（流畅最低≤33.33ms）、编辑p95<100ms、draw≤200、可见三角面≤350k、进程内存采样最大值<1.5GB、地图读取<5秒。帧时由实际墙钟逐帧采样，非引擎瞬时FPS；采样内存可能漏过瞬时峰值，不是VRAM。

## 功能操作复核（AC-01–13）

每项记“通过/失败/未测”、步骤和截图；发现作品丢失时停止在该档上继续写入，复制整个用户数据目录再报告。

| 用例 | 操作与观察 |
| --- | --- |
| AC-01 | 空白海面拖画草/沙/岩，笔刷调大后连续升降，右键取消、越边界、撤销整笔；同格一笔只升一次，岸线无裂缝 |
| AC-02 | 放屋后在支撑/门前尝试画海及升降；受保护格跳过、有提示，屋和居民保持 |
| AC-03/04 | 屋外圈2格花→3格花→撤销，比较预览和结果；邻海并有3格花时花园优先；整理→锁定，改花圃后保持，解锁重算，住户ID不变 |
| AC-05 | 新建屋、门前小路、向外海放码头（R旋转、−/+长度），给码头岸端接路；“入住”面板逐步说明缺什么，首次连通后10秒内迎客；断路和内湖不能迎客 |
| AC-06 | 两岸同高2–6格水面放桥，接路可走；尝试超长、异高、堵门陶盆，方案拒绝并有文字/预览反馈 |
| AC-07 | 居民去茶屋途中移动茶屋/拆桥，观察释放目标、安全暂歇和重选路；撤销后恢复，不穿水、不丢居民 |
| AC-08 | 完成愿望、收起另一条，暂停保存并重载；愿望、手记、身份、外观锁定保留，可展开收起条目 |
| AC-09 | 混合画地、移物、换色、锁定50次，连续撤销/重做；不重复物件，不撤回已经完成的愿望 |

写失败/备份/原子替换失败和16类损坏档已有源码自动注入：`godot --headless --path . --script tests/test_save_faults.gd`。该脚本只操作独立test文件，不要求测试者破坏自己的权限或主存档；打包版不附测试脚本，外部仍复核实际保存、备份与退出恢复。

用户目录：macOS为`~/Library/Application Support/Godot/app_userdata/Breezely Isles · 风屿手记/`；Windows为`%APPDATA%\Godot\app_userdata\Breezely Isles · 风屿手记\`。`island.json`及`.bak/.bak2/.bak3`为自动保存，`slot_1..3.json`为手动，`preferences.cfg`为设置，`photos`为照片。可由存档面板打开照片目录后到上级。交回存档前确认愿意分享自己的岛与槽名；无需实名、账号或网络。

## 5–8人、每人30分钟无讲解试玩

先取得文字记录同意；录屏另外单独征得同意，拒绝录屏仍可试玩。不收实名或在线遥测。每人用空白测试目录/新建无建筑海湾，避免前人完成状态干扰。观察者只读出目标，不给操作答案；求助和救援分别记录，卡死可救援但该步不计独立完成。

- 0–5分钟：画岸、放屋、说明下一步怎样接路。
- 5–10分钟：沿路接通外海码头，等第一位岛民；观察能否理解入住面板原因。
- 10–15分钟：屋外画花，问“你觉得房屋为什么变了？”；让其自行撤销一次，问是否相信能恢复。
- 15–24分钟：任选茶屋、温室或海边长椅，观察活动与手记；不要求同一时间强行完成六愿望。
- 24–30分钟：高处灯塔、切日落、摄影保存；最后问“如果没有奖励提示，还愿意再布置一个角落吗？”

填写RESULTS_TEMPLATE。按实际人数n计算阈值：画/摆/说明接路、解释变化、独立撤销三项各≥ceil(0.8n)，继续布置也按≥ceil(0.8n)。优先汇总作品丢失/流程阻断，再统计不理解、误删、卡路、UI遮挡的次数，附原话与时间点。小样本结果不用于市场成功率推断。
