# 体验优化计划 · 2026-11-11

目标是在相同建造工具下，让一次拖画、一次空间组合和一次居民回应产生连贯反馈。以可运行实现、固定机位对照和窗口输入回归验收。本轮完成下面五项后提交并推送当前分支。

| 阶段 | 实作 | 完成条件 |
| --- | --- | --- |
| P1 落笔连续性 | 建筑拖画显示真实体积预览；地貌笔显示预计的连续地表；取消清除预览，提交沿用同一候选 | 松手前世界数据不变，松手后与预览一致，跨界取消和整笔撤销通过 |
| P2 空间建筑 | 识别直排、转角、分叉和封闭庭院；连接生成不同构件，内院生成朝向院子的檐廊；主厅继续参与整体 | 同样的单元数在直排、L 形和围合中形成不同轮廓，拆开/移动/撤销实时重算 |
| P3 重复与节奏 | 按位置稳定分配少量立面细节，区分端头、转角和中段；新屋探出，旧屋的局部响应减轻 | 连建时邻屋不反复整体缩成薄片，手动形态与定形继续有效 |
| P4 创作引导 | 手记中提供基于当前岛屿的发现清单和下一笔建议，附能直接选择工具的操作 | 自由使用所有工具，可逐步发现连屋、改形、转角、院落和居民连通，不强制完成 |
| P5 生活因果 | 新来客与具体房屋关联的提示；手记根据实际道路/码头状态指出下一步 | 提示来自真实入住状态和建造结果，撤销/重载不增加虚构住户 |

庭院从实际建筑占用围出的空地推导，保留地表高度、路网、房屋身份及存档格式。建筑空间规则和视觉实现均为本项目原创。真实玩家的舒适度与持续游玩意愿还需要试玩判断。

验证采用三种组合的同机位截图、完整输入操作录像、原生窗口回归、旧存档与撤销检查。新增字段尽量派生，不增加玩家整理存档的负担。默认 Forward+ 和兼容模式均检查，Mac 导出包实际启动，Windows 包资源可在本机检查，Windows 系统启动待实机。

进度随实现更新到 STATUS.md，并记录本轮结果与未验证范围。

## 本轮完成记录

P1–P5 已完成实现与本机验证。建筑预览复用正式构件生成器；地貌预览复用未来表面采样，使用半透明覆盖展示降低后原本会被当前地表遮住的区域。方形框、入口与地基保护沿用原规则。贴墙候选保留玩家选择的合法方向，必要时尝试其他朝向。

空间规则按共享墙方向识别角色，洪泛外围空地后把剩余封闭区域判为庭院。庭院装饰是派生状态，打开一边、移动、撤销及读档时重算。原来的屋顶改形、外观定形、主厅、两轮风貌传播与居民身份保持有效。这里是本项目的空间启发式，没有声称复刻原版内部算法。
