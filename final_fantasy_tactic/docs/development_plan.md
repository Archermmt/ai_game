# 开发计划｜灰桥前哨 P0

版本：v0.1 · 日期：2026-11-12 · 状态：计划基线；实施已进入灰盒阶段，实际进度与证据见 [开发进度](development_status.md)。

本计划将 [PRD](prd.md) 的 P0 转为可以逐步验收的 Godot 开发任务。PRD 是玩法、数值、地图与内容范围的唯一依据；本文件负责顺序、依赖、职责、交付物和验证方法。概念图是视觉目标，不能替代规则数据或实机验收。

## 1. 首版交付与工作边界

首版交付是一场可独立启动、从战前说明玩到胜败结算并重新开始的全 3D 战棋：一张 12×10 高差棋盘、双方各三名固定职业单位、CT 行动顺序、移动、普攻、治疗、结束行动、合法敌方 AI，以及支撑判断的镜头、HUD、动画与声音。

优先交付 macOS 桌面鼠标键盘版本；其他系统导出在 P0 稳定后排期。P0 不包含职业树、经济、世界地图、战中存档、联网、多层桥下通行或每职业专属技能。P1 的少量技能选择和轻量编成须通过 P0 退出门禁后再做，不混入当前估时。

本项目以空工程起步，本计划最初用于策划交付。现已进入灰盒开发；下文为目标任务与门禁，实际已实现内容、测试与未完成项以[开发进度](development_status.md)为准，不能将计划条目视为通过记录。

## 2. 人力、估时与交付节奏

按 **1 名主开发配合 AI** 估算，包含规则实现、关卡搭建、简化角色与基础动作、自制或整理基础 UI/音频、逐步自测和导出检查。一个人日按约 6 小时有效制作时间计。AI 提高制作效率，但不代替策划判断、目标机验证和资产检查。

| 阶段 | 人日区间 | 阶段产物 | 依赖 |
| --- | ---: | --- | --- |
| M0 范围锁定与技术样板 | 2–3 | 规则检查清单、目标机记录、棋盘读数样板 | 本套策划文档 |
| M1 权威数据与规则底座 | 5–8 | 可重复运行的空间、CT、命令与战斗规则 | M0 |
| M2 玩家操作闭环 | 4–6 | 可操作的灰盒战斗、预览与确认反馈 | M1 |
| M3 敌方与完整单局 | 3–5 | 3v3 灰盒完整单局、胜败与重开 | M2 |
| M4 表现整合 | 7–11 | 场景、角色、动作、HUD、镜头、音效与音乐 | M3；可提前做不改规则的小样 |
| M5 调优与交付 | 4–6 | 首版可执行包、验证记录、已知问题与复盘 | M4 |
| 基础工作合计 | **25–39** | P0 可玩切片 | 不含 P1 |
| 风险余量 | **6–10** | 用于规则返工、资产导入、镜头遮挡和平台差异 | 按风险实际消耗 |
| P0 预算参考 | **31–49** | 包含余量的估算区间 | 非工期承诺 |

按每周五个有效制作日，约为 6–10 个制作周；兼职、外包等待和设备协调会增加日历时间。外包模型、动作或音乐的等待时间另列，不与有效人日混算。若要求接近商业作品的内容量、演出或资产精度，须重新估算。

## 3. 里程碑与退出门禁

### M0：先证明棋盘能读、规则能讲清

任务：

- 逐项核对 PRD 中移动、高差、占用、射程、弓箭 LOS、治疗、CT、取消和倒地规则；将歧义改回 PRD，再安排实现。
- 选定并记录实际 Godot 4.x 精确版本、渲染后端、macOS 版本、芯片、内存、分辨率与窗口模式。不以“最新版”替代具体版本。
- 建立最小工程、按功能组织目录、Git 忽略规则和设计源隔离规则；启用有类型的 GDScript 编写约束。
- 以方块、职业替身和基础高亮建立一个小样板，检查格子尺寸、四档高度、镜头四方向、拾取、脚底与血条位置。
- 在登记的目标机上确定 PRD 性能目标的测量口径；如果目标尚未定值，在本阶段冻结，之后保留同一设备和场景作比较。

退出门禁：一张对照图能明确指出“哪个格子、哪个高度、哪个单位”，旋转后仍能选择；规则清单无阻塞实现的歧义，工程可在目标机启动。M0 不把视觉样板记为战斗系统通过。

### M1：规则先于演出成立

任务：

- 定义只读职业/技能/地图配置和独立的战斗运行状态，建立稳定单位 ID、部署顺序、状态版本和战局实例 ID。
- 从棋盘数据生成四邻关系、合法占用、移动范围、路径与高度查询。所有单位均阻挡穿越和落点；可见台阶必须对应规则允许的边。
- 完成 CT 离散推进、就绪选择、溢出保留、死亡移除和时间线预测。输入与演出期间不推进 CT；时间线必须标出“假设其后结束行动”。
- 建立统一命令校验、预览与提交接口，覆盖移动、普攻、治疗、结束行动；玩家和 AI 共用。
- 命令提交一次性更新全部权威状态并生成表现事件。HP、MP、行动次数、占用、队列及胜败属于同一提交结果，动画不负责扣数值。

退出门禁：不加载角色模型也能完成一局规则推演；边界条件有明确拒绝原因；相同状态和命令得到相同结果。实现前先写有判别力的规则案例，自动验证不依赖截图。

### M2：玩家能看懂、能取消、能确认

任务：

- 打通“当前单位 → 移动或行动预览 → 确认 → 播放 → 返回指令 → 手动结束行动”。移动与行动可任意先后，两项用完只高亮结束按钮。
- 预览显示路径、落点高度、目标合法性、预计 HP/MP 变化、移动/行动使用状态；非法操作给出具体原因。
- 预览可取消且不改状态；已确认命令不可撤回。移动后取消攻击只回到指令选择，不回滚移动。
- 用状态版本拒绝过期预览，用明确的输入锁阻止双击、键鼠同时确认和表现期间提交新命令。
- 先接临时 HUD 与简化动画。确认后暂停 CT，并保持当前单位、目标、伤害与时间线对应。

退出门禁：近战、弓手、医师均可用鼠标键盘完整操作；连续点击、取消、换目标和镜头旋转不会重复扣资源或跳过行动。HUD 每次显示的变化与提交结果一致。

### M3：敌方会完成合法行动，单局能结束

任务：

- AI 先枚举合法命令，再按职业职责评分；近战争取接敌、弓手寻找射程与高地、医师在有效治疗和普攻之间选择。
- AI 支持先移动再行动、先行动再移动，以及只移动或直接结束。选定完整激活方案后逐条重验并提交；方案失效时仅在剩余预算内重新决策，不复用过期目标或重置行动次数。
- 设置每次激活的命令次数上限和结束兜底；无路、无合法攻击、满血或 MP 不足时正常结束，不能反复重试。
- 接入战前说明、清敌胜利、全灭失败、结算和重开；优先级与 PRD 一致。
- 重开创建新战局 ID，清空旧路径、高亮、队列和输入锁；旧动画、定时器、信号回调不得写入新战局。

退出门禁：连续完成至少三场独立灰盒单局，包含胜利、失败、重开；AI 在堵路、无目标和治疗资源耗尽时均能交还控制。每场记录命令序列与异常，不把“AI 会行动”当成“AI 有挑战性”。

### M4：将战术读数落实为画面和声音

任务：

- 按概念图建立模块化石地、草边、台阶、墙体和障碍，检查美术摆放与权威可走格一致；不引入看似可通行的装饰路线。
- 使用共用比例与骨架方案制作三职业，双方以队伍标记及配色区分；武器和轮廓在实际战斗缩放下可辨识。
- 完成待机、移动、攻击/施法、受击、倒地；移动脚底贴合高度，受击时点对应表现事件。动画只消费结果。
- 完成镜头旋转/缩放、遮挡处理、当前单位定位和 HUD；血条不被场景遮住，范围提示兼用颜色、边框和符号。
- 接入选格、确认、拒绝、命中、治疗、倒地、胜败音效与一首战斗循环曲，分别调节音量并检查循环边界。
- 建立资产来源、授权、可编辑源、导出及导入设置记录；概念图不直接充当可操纵角色或地图资源。

退出门禁：所有职业、路径、目标与高度在四个镜头方向均可读；表现播放完毕后权威状态与显示一致；完整单局可感知命中、治疗和倒地反馈；实际资产导入与目标机性能均有记录。

### M5：以玩家任务验收，不以功能数量验收

任务：

- 完成下方验收矩阵，记录版本、操作、预期、实际、设备与证据。规则检查与实机检查分别留证。
- 邀请至少三名未参与制作的试玩者，观察目标理解、首次操作、路线选择和失误原因；样本仅作设计线索。
- 检查目标 8–15 分钟单局节奏与职业分工是否成立；数值与路线调整回写 PRD，并重跑受影响规则案例。
- 固定测试场景检查帧耗时、预览响应与 AI 思考耗时，区分 AI 决策时间和表现播放时间。不能用低面数或编辑器 FPS 推断导出性能。
- 在登记的目标机运行导出包，覆盖全新启动、完整胜败、重开、音频和退出；查看错误日志与资源缺失。
- 整理可执行包、启动说明、已知问题和当前版本验证记录；再根据真实结果沉淀案例实践。

退出门禁：P0 验收项全部满足；无卡住单局、状态破坏、无法选择关键格子或预览结算不一致问题；遗留问题明确影响与复现方式。未实测的设备、性能、兼容性不得标记通过。

## 4. 数据与模块责任

| 模块 | 拥有什么 | 不负责什么 |
| --- | --- | --- |
| 配置定义 | 职业、技能、棋盘、出生点、部署顺序等只读定义 | 不保存各单位当前 HP/MP |
| BattleState | 当前单位状态、格子占用、CT、行动使用状态、胜败、状态版本和战局 ID | 不持有模型、HUD 或动画节点 |
| 空间与规则服务 | 由快照计算可达、路径、射程、LOS、伤害和治疗 | 不根据碰撞网格另定一套玩法 |
| 命令服务 | 校验请求、预览结果、原子提交、发布结果事件 | 不等待动画回调才结算数值 |
| 行动调度 | CT 推进、就绪选择、激活与结束、时间线副本预测 | 不在玩家思考或演出中推进时间 |
| 输入与 HUD | 发起请求、显示快照和预览、管理当前交互阶段 | 不私自改占用、HP、MP 或 CT |
| AI | 通过相同合法命令接口选择方案 | 不绕过校验或直写单位状态 |
| 表现层 | 从状态和事件驱动模型、动画、镜头、音效与特效 | 不维护第二份战斗真相 |

规则定义可使用 Godot 自定义 Resource，运行实例状态单独创建；共享配置运行时保持只读。P0 不增加完整存档框架、跨地图系统、全局大管理器或为六个单位提前引入线程池。只有测量证明需要时才增加并发与缓存。

推荐工程目录是后续创建方案，当前文档交付不代表已建立：

```text
res://
  features/
    battle/
      board/          # 格子数据与棋盘显示
      units/          # 单位定义、实例与角色表现
      rules/          # 纯规则、预览和命令提交
      turns/          # CT 与行动调度
      ai/             # 合法候选与决策
      presentation/   # 事件演出、效果与战斗镜头
      hud/            # 战斗信息与交互
    flow/             # 战前、结算与重开
  levels/             # 关卡定义与场景
  common/             # 少量跨功能通用约定
  tests/              # 规则与集成验证
  docs/               # PRD、计划、概念图与验证记录
```

资源和脚本使用 snake_case，场景节点使用 PascalCase；场景内稳定引用使用唯一节点名。`.godot/` 不进入版本控制；设计源与文档目录设置 `.gdignore`，避免把概念图和制作源误当运行资产导入。全局服务仅在确有跨场景生命周期时引入。

## 5. 输入、提交与演出的契约

| 阶段 | 允许的输入 | 数据变化与离开条件 |
| --- | --- | --- |
| 等待激活 | 查看战场、镜头操作 | 无就绪单位时由调度推进 CT，选择当前单位 |
| 选择指令 | 移动、普攻、治疗、结束、查看信息 | 不直接改状态；不可用指令显示原因 |
| 预览 | 选落点/目标、确认、取消、查看结果 | 只计算候选；取消回到指令，无资源消耗 |
| 提交 | 只接受当前有效确认一次 | 校验战局 ID、状态版本、当前单位、次数、资源和合法目标；失败保持原状态 |
| 播放 | 查看信息、允许范围内的镜头操作 | 输入锁阻止新命令；播放提交产生的结果事件，不再次扣资源 |
| 返回指令 | 继续使用未用项，或手动结束 | 两项用完仍需玩家结束；AI 由策略调用结束 |
| 结算 | 查看结算、重开 | 停止调度；重开替换整个战局并清理旧表现 |

播放异常不得形成永久输入锁。为每条表现事件设完成/超时收口，异常时将显示同步到已提交状态并解锁；是否重播仅影响表现。暂停同时冻结 AI、演出及其超时计时，只累计非暂停耗时，避免长时间暂停被误判为失败。旧战局回调即使稍后到达，也因战局 ID 不符而丢弃。

## 6. 关键验证矩阵

以下是待执行标准。自动检查用于规则和状态，实机检查用于输入、镜头、画面、音频与导出；两者不能互相替代。

| 编号 | 场景与操作 | 应看到的结果 | 首次执行 |
| --- | --- | --- | --- |
| V01 | 比较相邻高差 0、1、2 的格子；检查边界、斜向及单列重叠 | 只有 PRD 允许的四邻边可走；无斜穿、跳高和第二可站面 | M1 |
| V02 | 友军/敌军占住必经格与落点，随后有单位倒地 | 存活单位均阻挡；倒地一次性释放占用，显示消失不决定规则时点 | M1 |
| V03 | 同一目标有等长路径、不可达路径、刚好够步数与差一步 | 路径选择稳定，可达高亮和实际移动完全一致 | M1 |
| V04 | 全体 CT 为零按初始属性推进 | 第 9 tick 两名弓手 CT 同为 108，先我方弓手再敌方弓手；结束后各保留 8，期间无额外 tick | M1 |
| V05 | CT 同值并列、超过阈值、死亡及仅剩一方 | 按 CT 和部署顺序稳定选择；溢出保留；死亡从队列移除；胜败后停止推进 | M1 |
| V06 | 镜头操作、预览停留、慢速播放，并比较时间线与实际后续 | 思考和演出不推进 CT；按预测假设结束时，未来顺序与显示一致 | M2 |
| V07 | 移动→攻击、攻击→移动、只移动、只攻击、直接结束 | 每激活最多各一次；两项用完不自动替玩家结束；结束统一处理 CT | M2 |
| V08 | 取消移动预览；确认移动后取消攻击；预览期间目标失效 | 未提交状态不变；已移动位置保留；过期预览被拒且不扣资源 | M2 |
| V09 | 双击确认、键鼠同时提交、播放中反复点击 | 仅一次状态提交和结果事件，无重复伤害、扣 MP 或结束 | M2 |
| V10 | 近战/弓箭射程边缘、不同高差、高处射程延长与墙体 LOS | 可用提示、预计伤害和实际结果一致；单位不挡弓箭，实心地形按 PRD 判定 | M1/M2 |
| V11 | 治疗自身/友军、满血、差额不足 36、MP 不足、隔墙目标、空格和倒地目标 | 距离/高差与 MP 合法且目标为存活友方才可提交；恢复封顶；满血拒绝；治疗完全忽略 LOS，可跨障碍 | M1/M2 |
| V12 | 单次致死、最后敌军倒地、最后我军倒地、构造同次双灭 | HP、占用、队列与胜败同次更新；双灭按失败优先；无重复结算 | M1/M3 |
| V13 | AI 被堵住、弓手贴近、医师无 MP、全队满血、无合法目标 | 所有命令合法；无效候选不重试到死循环；最终结束激活 | M3 |
| V14 | 表现未结束时触发受控重开，旧回调随后完成 | 新战局位置、HP/MP、CT、HUD 和输入锁均为初始状态；旧回调无效 | M3 |
| V15 | 四方向镜头、最高/最低层、建筑背后、最远单位、HUD 覆盖区 | 格子与角色可正确选中；HUD 不穿透点击；高度、血条和职业仍可读 | M0/M4 |
| V16 | 目标机导出包完成胜败、重开、音频循环与退出 | 无缺资源或卡住流程；实测性能满足冻结目标；循环无明显接缝 | M5 |

每次改动只重跑受影响规则及关联流程；已通过且未受影响的检查不机械重复。规则改变、依赖升级、导出差异或新失败证据才扩大验证范围。M5 的完整单局回归是最终集成检查。

### 6.1 目标机性能测量口径

M0 登记机器型号、芯片、内存、系统、引擎精确版本、渲染后端、阴影和后期设置。M5 使用同一配置的导出构建，1920×1080、六单位、正式地形、常用阴影和特效；先预热 10 秒，再以固定命令回放进行 3 次各 120 秒采样。回放应包含静态思考、四向旋转、移动、射箭和治疗；使用验证夹具维持六单位，避免倒地减少负载导致比较失真。

记录平均 FPS、p95 帧时间、峰值与发生位置；后端允许时同时记录 CPU／GPU 帧耗时。以 PRD 的常态 60 FPS 和 p95≤20ms 为目标判定，异常峰值单独定位，不用平均值掩盖停顿。同时记录移动／能力预览请求到显示耗时（目标≤100ms）与单次 AI 决策耗时（目标≤1秒，不含演出）；重复运行定位波动来源。

若未达到目标，先调整阴影、透明、装饰与表现开销，再用相同回放复验；只有明确记录目标变更原因并同步 PRD 后才可更换性能基线。测试数值与截图写入后续验证记录，当前没有测量结果。

## 7. 风险与控制顺序

| 风险 | 提前发现的方法 | 处理原则 |
| --- | --- | --- |
| 高差规则与模型不一致 | M0/M1 开启格子、高度、占用调试视图对照 | 先修权威规则与显示映射，不用碰撞补丁掩盖 |
| 预览、AI 与结算分别实现 | 让三者消费同一状态快照与规则结果 | 收敛接口；不通过数值碰巧相同视为解决 |
| CT 在思考/演出时漂移 | 固定初始状态比较不同等待时长的队列 | 单一调度入口，明确暂停条件，稳定并列顺序 |
| 动画回调造成重复结算或重开污染 | 连点与旧战局回调案例 | 提交后只播放事件，战局 ID 和输入锁覆盖生命周期 |
| 职业只剩数值差异 | 观察两条路线与治疗位置是否改变选择 | 先改地形和职责反馈，再考虑 P1 技能 |
| 制高点成为唯一解或弓手独强 | 对比占高地、侧路推进和优先压医师的玩法记录 | 在 PRD 中调整路线、射程或部署，重验受影响项 |
| 模型、动作与遮挡成本超预算 | M0 小样和 M4 实际缩放检查 | 共用骨架和少量动作；先降低装饰密度，保留战术信息 |
| 过早扩职业/剧情/插件 | 每阶段核对 P0 清单与退出门禁 | P1 独立排期；插件先做小样并记录版本/许可/导出结果 |

如工期不足，优先削减装饰种类、镜头过场、特效复杂度和次要动作变化；移动、CT、预览一致、取消、合法 AI、胜败与重开属于体验闭环，不作为默认削减项。
