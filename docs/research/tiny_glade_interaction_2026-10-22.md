## 对当前游戏的诊断

以代码版本 `ef9ac49` 为基准检查 `garden_hud.gd`、`garden_playground.gd`、旧周属性组件及输入路由：

| 当前流程 | 复杂度来源 | UX-02方向（本项目设计，非原版事实） |
| --- | --- | --- |
| 底栏12项，另有“修改”；点工具弹大卡片 | 创建与修改分为两个模式，参数先于意图出现 | 底栏对齐11类；任意工具下右键对象就地修改；选择工具不自动打开大卡片 |
| 先选择房屋列表，改宽/高/深，再提交 | 操作视线离开场景，需要理解属性和提交阶段 | 在建筑旁拖“宽/深/高/移动”手柄，松手提交一次 |
| 物件移动/旋转/缩放靠数值与应用 | 每个动作都需要菜单往返 | 选中后移动/旋转/大小手柄，复制/删除为短操作条 |
| 门窗依赖先选目标房屋 | 先选房屋的顺序隐藏，容易无反应 | 放置时根据指向墙面自动找到房屋，反馈目标与冲突 |
| 桥/阶松手后还需“确认桥/阶” | 同为拖绘，却和屋/路提交规则不同 | 合法松手即提交，失败整笔回退并显示原因 |
| 草密度与刷植参数堆在大卡片中 | 把性能偏好和种植操作混为一体 | 花草小条保留刷径和地表草密度；高级分类/数量在更多参数中 |
| 原版后续有任意屋顶塑形、分组旋转等 | 直接照搬会扩大现有MVP几何能力 | 先统一现有P0的操作模型，不显示本项目不支持的手柄 |

建议的统一规则：选工具 → 在场景创建；点物体 → 就地修改；拖动预览 → 松手生效；错误/取消 → 原作品和历史保留。快捷键是加速入口，核心流程可纯鼠标完成。精确参数保留为可选入口。
