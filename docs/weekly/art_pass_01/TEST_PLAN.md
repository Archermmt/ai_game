# ART-01 验证契约

本轮是用户批准的美术返工，不是 W10 功能周。批准 PRD、原资产表与 W01–W09 历史门槛保持基线。

## 自动门槛

```bash
python3 tools/quality/art_pass_checks.py
```

先运行 W01–W09 的 446 项和逐周重启/故意失败负控，再执行 ART-01 源件、GUT 与跨进程重启。
测试断言失败、脚本解析/运行错误、空套件、少于45项新增用例或跳过项均使脚本失败。
CI 改用这个入口。全新检出会重新导入，不能依赖本地 `.godot`。

| 范围 | 有效验证 |
| --- | --- |
| 建筑14项 | 原墙、真实洞口、曲墙门洞、屋面封闭、两端尺寸预算、四绘制件、同高/高低/错位贴靠、山墙接缝；装饰不改源 |
| 植被11项 | 全部导入模型的顶点/法线/UV/风权重、根固定、双LOD、图集与材质复用、批次姿态/相位/包围盒、派生确定性 |
| 布局3项 | 示范/空布局合法与同地形、现有存档格式往返、石路随机偏移后仍遵守建筑/池岸遮罩 |
| LOD2项 | 所有高低角色使用同一包围盒中心，批次包围盒覆盖各源实例；避免只露出内部树冠的切换空档 |
| 森林4项 | 树幕连同最大冠幅在48m核心外、原20棵源树不变、种子确定性、外部地面落脚 |
| 实机场景11项 | 异步原子发布、石路编辑/撤销、远处节点复用、无效输入、风/摄影恢复、50混合编辑+50撤销+50重做、空入口、真实保存/载入新旧作品、种子缓存、拾取体、新绿篱及撤销 |

Headless Dummy renderer 不保留 MultiMesh GPU 数据。它只验证实际导入几何与 CPU 描述，不能冒充 GPU 验证。
原生 catalog 用 `WINDHAVEN_ART_NATIVE_BATCHES_REQUIRED=1` 强制 GPU 读回；误用 headless 会失败，不跳过测试。

## 原生画面与性能

```bash
python3 tools/quality/art_pass_render_checks.py
python3 tools/quality/art_pass_orbit.py
python3 tools/quality/export_smoke.py --week 9 --art-pass
python3 tools/quality/clean_checkout.py --week 9 --art-pass
```

原生脚本串行拍日/暮、近/远、四向、低角度、空布局、100/150%入口；验证摄影三尺寸、失败重试和源/相机/选择恢复。
`--art-fhd --qa-settings` 将内部渲染视口固定为1920×1080，PNG头部必须匹配，防止 macOS 窗口被屏幕宽度限制后仍以逻辑尺寸冒充1080p。
普通试玩保留原窗口/输入策略；图片导出继续使用独立视口。
60秒墙钟采样分别覆盖示范静止、20次局部编辑及24建筑/1000实例容量编辑；统计帧时间、端到端提交及进程RSS。
性能命令成功表示采集完整，目标失败仍写入 JSON 并作为开放缺陷。Windows 真机和最低配置另验。

QA 使用独立 `qa_art_01_*` 目录；原生脚本比对正式 `week_08/saves` 与 `preferences.cfg` 哈希。
不修改用户作品。模型变更还需 Blender 重开源件审计，GLB可读不等于源件可编辑。

## 视觉门槛

人工复核真实 Godot 多角度图片与360°录像，对照 C01/C03/C04：大轮廓、屋顶厚度、叶簇、冷暖与生活感。
自动测试不判定“符合吉卜力”。视觉样板交用户复核后再决定后续美术取舍；概念中的 P1 藤蔓、雨棚与炊烟仍按原范围保留。

归档日志仅清理行尾空白和末尾空行；本地 `reports/art_pass_01_clean_evidence/` 保留原始输出，测试消息和结论不变。
