## 目标与范围

把现有地表草改善为更连贯、柔软的手绘草丛，在俯视和1.65m林间漫步中都成立，同时保持可编辑、撤销、存档、四季、风与摄影。先从2种低面草卡、1种低草开始；少量精细前景草只有在明显提升效果且满足预算时纳入。

集成限于现有地表草和灌草的渲染变体。复用确定性散布、8m分块、异步生成与事务，不增加新地图、植物玩法、GeoScatter运行依赖或完整Blender演示地形。树、房屋、石头继续作为同场风格参照；若需要整体再改，单列下一轮范围。批准PRD原文保持。

所有阶段归档到[W14执行台账](weekly/week_14/README.md)。W14是本次集成批次的证据编号，当前交付G0及G1–G3本地样板，不预先改游戏版本或宣称全批次交付。

### 验收节点 G0

## G2：8×8m局部对照，确认风格方向

### 要做的事

- 在现有屋前放入8×8m试验区，含路径、石头、树荫和缓坡；建筑/树石/天空/曝光沿用基线。
- 同一相机和同一世界源状态一键切换“现有草 / 新草”，只切派生渲染。固定天气、时刻、风相位与TAA收敛条件后导出A/B；不并行渲染两个世界来掩盖成本。
- 按新草的实际面积重定间距、候选抽样、缩放与疏密分组。45%仍是用户设置的默认值，但记录新旧实际实例数和覆盖差异，不宣称相同百分比必然同等密度。
- 调整草根与地面颜色和世界空间低频色块，做路径边缘渐疏与林下冷绿；不为此次试验改整场曝光来“美化”新草。

### 验收节点 G2

- A/B切换前后WorldDocument源状态、revision、撤销/重做栈、作品/偏好哈希一致；关闭预览不会改正式场景。
- 平地/缓坡草根贴地，根部高度与当前地形采样误差≤2cm；自动草对路径、入口、池岸和桥头沿用现有合法边界。边缘宽草卡的覆盖需检查，不能只保证原点不落在路上。
- 至少交付俯视全景、屋前低机位、路径边缘、树荫、逆光五组同机位新旧图；新旧使用一致画质/曝光，关闭景深也成立。
- 小规模轨迹无新增长帧或脚本错误；材质/实例统计可读。完整性能签核留到G4，不以局部顺畅代替容量结论。

**用户体验**：“局部对照”里切换新旧，俯视旋转后进入漫步，沿路径走进树荫；可切日间/黄昏和暂停。优先判断草地是否更连贯、是否保留呼吸感、是否像覆盖了一层贴纸、是否与树石房屋协调。

**G3推进记录**：G2交付后用户明确要求继续后续任务，本轮据此进入G3；V2未收到具体验收评价，仍标为待体验。

**视觉节点 V2**：记录用户“接受方向 / 需调整 / 未评审”。用户接受后扩展到G3；未评审时可完善导出/测试和当前样板，不把沉默记为美术通过。若整体方向不喜欢，停留在局部调材质和密度，避免铺满场景后再返工。

### 要做的事

- 对接天气/季节/积雪、风、减少动态、摄影冻结和导出；需要时用遮罩区分草叶与花瓣，防止整张图集一同染黄。
- 处理宽草簇坡面贴合、建筑/池岸附近的覆盖与风动包围盒。新增草默认继续排除地表草的平面反射层，不无意增加反射负载。

### 验收节点 G3

- 刷草、擦草、抬低地形、移动/改大小房屋、改路径/池岸/桥头后，未影响区域实例的种子/姿态/渲染变体保持一致。

- 混合编辑50次再逐笔撤销重做，恢复源状态与派生结果；存读档后重新生成一致，旧作品无强制新字段/格式迁移。源ID、手放植物与锁定内容不丢失。
- 四季×晴/阴的8组代表图，加雨、雪与天气重定向轨迹；摄影冻结/解除、减少动态、1080p/2K无UI导出均通过。冬雪检查结合现有`living_up`语义，避免新草整片异常挂雪。

**用户体验**：“编辑庭园”里新建/调整一间房、画路径、刷坡，撤销/重做后进入草地漫步；切秋天/冬天和雨雪，暂停风并拍照。用户可以保存预览作品，下次从专用预览槽继续体验。

**进入G4条件**：编辑正确性与环境接口通过，用户反馈没有尚未处理的关键视觉问题。若此时无反馈，可先跑容量测试，但仍不能宣称视觉已接受或替换默认入口。

## G4：满容量与Mac画质预算

### 要做的事

- 使用现有24屋/1000源压力布局，确认实际树/灌草/道具构成；派生地表草另计。维持相同种子、编辑动作和相机轨迹，新旧各测。
- 设计近/中/远表现与密度，不先承诺固定LOD距离。8–12m近景、12–30m草卡、30–50m逐渐交给地面色块仅作起始试值；依据俯视/漫步实测收敛。主模型只选2–4种、1–2共享材质起步。
- 主性能使用锁定Godot4.7.2 / Metal Forward+、真实1920×1080帧缓冲；1080p是游玩门槛。2560×1440摄影测导出正确性和峰值成本，额外记录2K实时表现，不自动增加2K实时60fps承诺。
- 所有GPU检查串行，不同时运行Blender渲染、其他游戏窗口或双场景对比。记录电源/低电量模式、画质、风、密度、机型与热机条件，不存硬件序列号。

### 验收矩阵与门槛 G4

| 检查 | 采样要求 | 通过或记录规则 |
| --- | --- | --- |
| 默认45%草：晴天、暴风雨、暴风雪、沙尘暴 | 每个场景新旧交替运行，各3次独立进程；每次60秒固定行走/环绕 | 每次帧p95≤20ms；报告p50/p95/p99/max，不合并样本掩盖失败 |
| 100%草：晴天、当前最重天气 | 同上，各3次60秒 | 同样检查20ms门槛；失败则记录该设置未通过，优化或明确限制该档，不把它算默认通过 |
| 编辑：改屋、门窗与刷地/草 | 同条件3轮，每轮≥20笔，冷启动/首笔和稳态分别列出 | 局部详细结果p95目标≤150ms；原已知首笔/密集拖拽缺口逐项保留；新草不得新增回归 |
| 大范围编辑 | 固定大笔刷与连续取消/重定向 | 输入阻塞≤100ms、详细结果目标≤500ms；分别记录回调、提交与草稳定时间 |
| 20分钟混合编辑/漫步 | ≥50次撤销重做、10次存读档，含天气 | RSS≤2GiB，无持续增长、错误/泄漏/内容丢失 |
| 2K摄影 | 2560×1440输出，可解码、正确尺寸、无UI | 无崩溃；冻结/返回正常，源/构图/偏好不变；报告峰值内存 |
| LOD与透明边缘 | 静止、慢转、快转、强风/逆光/树荫 | 无明显露底、黑片、边缘闪烁、草根漂浮和突跳，留截图/短视频人工复核 |

额外用新旧同条件帧p95增幅15%作**诊断报警线**，不替代20ms正式门槛；超线需解释与定位。GPU时长若当前接口不能可靠获取，明确填“不可用”并记录真实CPU/帧间隔与RenderingServer统计，不把帧间隔冒称GPU耗时。

**用户体验**：“满容量”提供默认/最高草、晴/恶劣天气切换，可走动和旋转，显示简单帧时间/FPS；详细技术数据留在报告。用户实际感受顺滑度、草是否抢视觉、远近切换是否突兀，不要求用户手工跑测量脚本。

**进入G5条件**：默认档游玩与内存预算通过、没有由新草引入的编辑/正确性回归。最高档或历史编辑尖峰未过要保留明确缺口，不把集成阶段完成记为整个产品M4/M5放行。

## G5：候选体验、记录与回退

## 证据与阶段决定

每阶段证据放 `docs/weekly/week_14/evidence/painterly_grass/g0/` 至 `g5/`，至少包含：提交/工具版本、实际测试数、日志/JUnit摘要、源/资产哈希、before/after同机位图、性能原始数据（适用时）、已知问题、下一步决定。运行中的临时产物放忽略的`reports/`，只归档必要证据。
