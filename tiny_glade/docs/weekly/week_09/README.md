## 原生性能结果

设备 Apple M4 Pro / 20核GPU / 48GB / macOS arm64；发布包 Forward+ / Metal，1920×1080，沿用当前MVP默认渲染参数（中档基线）。
每组预热2秒后按真实墙钟记录60秒；编辑只在前段发生，因此另列提交最大值，不用整体p95掩盖编辑峰值。

| 场景 | 帧间隔p95 | 提交最大 | 进程RSS峰值 |
| --- | ---: | ---: | ---: |
| 满容量静态 | 16.667 ms | — | 647.38 MiB |
| 满容量20笔局部编辑 | 17.676 ms | **205.478 ms** | 741.12 MiB |
| 满容量8笔9m大刷 | 18.056 ms | 462.335 ms | 744.25 MiB |
| 半密度20笔局部编辑（40树/400林下/60道具；仍24体块/1池/2桥） | 12.963 ms | **152.608 ms** | 645.23 MiB |

帧p95≤20ms、大改≤500ms、RSS≤2GB在本机通过；局部≤150ms **未通过**，半密度仍超2.608ms。
主线程已测回调最大43.049ms、发布20.511ms、准备切片2.835ms；这些测量不替代物理输入到屏幕的端到端延迟。
源准备约0.51–0.52秒；修正首帧探针后另作三次满容量启动，进程启动至首个原生绘制1.395 / 1.427 / 1.421秒，通过暂定5秒目标。
最初stdout缓冲使首帧标记无法及时读取，原60秒数据保留；加载结论来自单独的5秒启动试验，不修改旧帧样本。

[汇总与目标布尔值](week_09_render_checks.json)、[帧序列/RSS采样/日志/截图](stress/)。
60秒测试使用初版W09发布包（源码 `34d9cdc`，[包哈希](week_09_stress_build.json)）；随后改动为QA首帧标记和摄影UI/关窗修复。
最终发布包与原生摄影使用修复后实现；最终包哈希见[导出记录](week_09_exports.json)。
没有GPU硬件计时样本，保持null/0；RSS不等于全部统一GPU显存。最低配置与Windows真机仍未验。
