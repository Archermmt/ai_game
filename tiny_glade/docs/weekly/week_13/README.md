### 如何体验

- 打开新示范看地貌；地形原有抬高/降低/平滑等操作仍可用。旧存档不会被强行重造地形。
- 点建造卡片后，在小屋、圆屋、围栏、桥、阶等图片中选择；其他类别使用相同图片操作方式，悬停可读说明。
- 日历采用**虚构360日历**，每月30日，不读取现实日期，也不计算离线进度。3–5月春、6–8月夏、9–11月秋、12–2月冬；可直接选4/7/10/1月查看四季。
- 1倍速为每现实秒推进一游戏分钟，60倍为每秒推进一游戏小时。Speed控制历法/日照；风雨保持自然运动节奏。天气可以自由搭配季节。
- 日期/天气/速度随作品保存；手动更改会提示未保存，自动流逝不产生建造事务、撤销记录或几何重建。
- 摄影冻结同时定格历法、云、雨雪和闪电，退出恢复；减少动态会禁止闪电并放慢天气运动。

## 模块与数据

`features/living_world/`内分为CalendarState、CalendarPanel/LivingHud、LivingAtmosphere、TerrainRelief、IllustratedIcons及装配根LivingPlayground。原建造、约束、重建和撤销管线继续使用。

地形是解析的种子高度profile，复用原分块网格/射线/支撑/草查询及后台重建。实例`position.y`是支撑相对偏移，**保留原值**；派生pose负责贴到新高度，不能把地面高度再写入源偏移造成浮空。新profile进入原缓存签名。

日历保存在版本化存档`presentation.calendar`；旧档无此字段时提供默认历法，并将旧黄昏设置映射为17:30；日历统一控制窗光，切回白天不会残留亮灯。验证有限数值、日期范围、速度枚举、天气和最大年份。新应用读取旧档，旧包不提供本轮功能。

季节与云影用GPU共享uniform，不逐帧重建网格。天气固定两个MultiMesh：雨1400个、雪900个，实际只显示当前类型；无逐粒子CPU更新。树叶使用材质裁切，积雪为材质覆盖，云影为程序投影；没有新增流体、体积雪、天气音效或植物生长模拟。Blender源件、导入设置与锁定工具版本未改。
