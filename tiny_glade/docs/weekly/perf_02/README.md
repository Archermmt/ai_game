## 实现与正确性

1. 每次重建为不可变快照建立高度增量空间索引，只查询相交桶，再恢复原输入顺序。负坐标、闭边界、乱序、spacing、采样halo和极大范围与原全扫描一致；完整源校验保留。
2. 风材质按实际根节点身份复用；新增、替换、删除、种子、池岸及撤销会失效。集合与递归扫描相同，色板、风和摄影冻结继续生效。
3. 草分布键仅包含实际二维避让依赖。屋顶坡度、墙高和窗等不改变分布的修改复用原草；占地、入口、池域、道路、桥梯、道具范围或种子变化仍重算，地形高度按块失效。
4. worker批量生成与原变换、相位、次序一致的MultiMesh缓冲。发布端只替换变化块，版本依据已发布状态；未发布或已取消的结果不能当作live，取消不能释放live节点。
5. 空结果、0/100%密度、撤销、取消及工作中退出均有回归。满容量保持34,006簇、15,285可见实例；最后一次局部地形编辑重建2块、复用34块。

详见[测试契约](TEST_PLAN.md)。没有修改Blender生成器或`.blend`源件，不声称新增源件重开审计。

## 退出修复与失败记录

曾出现2个/8个/10个ObjectDB残留，严格日志门禁均拒绝。详细日志把其中8个识别为四组音频stream/playback；10个那次未逐个识别。初次调整场景销毁顺序不足以关闭问题，短流程未复现也未当作修复证据。

随后发现普通`SceneTreeTimer`会扣除整帧delta，包含创建前的帧内耗时；[Godot4.7.2源码](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/scene/main/scene_tree.cpp)支持该时间基准差异。退出改为声音停止时建立单调时钟截止点，实际等待至少400ms，再释放场景并排空两帧；不改音频停止顺序或关闭声源。新增回归：常规50ms实测51.309ms，前置150ms长帧后仍等50.235ms。最终三组60秒、两组阶段、六组真实输入及GUI进程均无退出残留；真实CoreAudio验收继续独立待做。

GUI探针原有150%摄影前置条件可能零手柄也通过，现要求同一屋顶可见，再在摄影返回后不重发输入检查同目标；记录系统与合成指针。中间一次追踪发现原生鼠标运动覆盖合成位置，保留为失败，未以OS warp或直接赋hover状态绕过。最终25项通过。

[diagnostics/](evidence/diagnostics/)保留修复前失败日志、退出诊断、计时回归、GUI追踪和原`0ee97be`容量通过样本的来源。早期“0.4秒/300ms等待”仅为timer设定值，不能据此认定实际已等足。上述历史失败不混入最终975a367通过收据。
